# サーボの試験と較正（mini-r2）

最終確認日: 2026-11-18。対象: 作る機体 `mini-r2`（MG90S × 8、ESP32-S3）。

**この文書のプログラムは、パソコン上のテストで確かめただけです。** ESP32 に書き込んだことも、
実物のサーボで動かしたこともありません。ESP-IDF（ESP32 用の開発環境）も、まだ入れていません（§9）。
実物で試して違っていたら、この文書を直してください。

## 0. この文書でやること

サーボを脚に付ける前と後に、次のことをします。

1. サーボを**1個ずつ** ESP32 につなぎ、動くか確かめる（ホーンを付ける前。§5）。
2. サーボを**中立**にして、ホーン（と脚）を付ける（§6。組立は [assembly-guide.md](assembly-guide.md) §4.5・§4.7）。
3. 脚を付けたら、関節ごとに **中立のずれ・向き・動ける範囲** を測り、ESP32 に保存する（§7）。
4. パソコンで結果を受け取り、検査して、方策の書き出しに渡すファイル（`servo.json`）を作る（§8）。

ESP32 のプログラムは、何も指定しないと**この試験・較正モードで起動し、方策（歩き方を学んだプログラム）は動かしません**。

## 1. 言葉の意味

| 言葉 | 意味 |
|---|---|
| パルス幅 | ESP32 がサーボに送る信号の長さ（µs、マイクロ秒）。サーボはこの長さで角度を決める。500〜2400 µs で約 180°（推定値） |
| 中立 | 関節角 0 の位置。この機体では、組み立てた**立った姿勢**（[assembly-guide.md](assembly-guide.md) §4.1 の図）。名目では 1450 µs |
| 関節角 | 立った姿勢からの角度[度]。**プラスは足先が後ろへ動く向き**（股も膝も。膝のプラスは脚を伸ばす向き）。学習のモデルと同じ取り決めで、テストで固定している |
| 向き（sign） | パルスを増やしたとき、関節角が増えるなら +1、減るなら -1。左右のサーボは向き合って付くので、左と右で逆になるはず（名目では左 +1、右 -1。実物で確かめる） |
| 範囲の端（lo / hi） | 関節を動かしてよい端。lo は足先が前の端（股は脚を前へ振る、膝は曲げる）、hi は足先が後ろの端（股は後ろへ振る、膝は伸ばす） |

学習で使う関節の範囲（[hardware-spec.md](hardware-spec.md)「関節の可動域」）:

| 関節 | lo の側（足先が前） | hi の側（足先が後ろ） |
|---|---:|---:|
| 前脚の股 `hip_lf`、`hip_rf` | -45° | +20° |
| 後脚の股 `hip_lh`、`hip_rh` | -35° | +45° |
| 膝 4本 | -60°（曲げる） | +45°（伸ばす） |

測った範囲がこれより狭いと、方策が出す角度にサーボが届きません。そのときは §8 の検査が止めます。

## 2. 安全のきまり

**人の側で守ること**

- 電源は **5V だけ**。スマホの充電器（USB-PD で 9V・12V を出すものがあるので注意）か、5V 4A の AC アダプタを使う。
- **サーボの電源（赤い線）を ESP32 から取らない。** 5V の電源から直接取る。**GND（茶色の線）は ESP32 の GND とつなぐ**
  （[esp32-deployment.md](esp32-deployment.md) §8、[assembly-guide.md](assembly-guide.md) §5）。
- 最初は**サーボを1個だけ**つなぐ。1個ずつ増やす。
- **ホーンや出力軸を手で回さない**（特に電源が入っているとき）。中のギアが欠けます。
- 脚を付けたあとは、ロボットを箱などに載せ、**脚が床や手に当たらない**ようにする。
- 「ジー」と鳴り続ける、熱くなる、変な動きをする: すぐに `off` と打つか、**5V の電源を抜く**。電源を抜くのがいちばん確実です。

**プログラムがしていること**（ホストのテストで確かめた。実機では未確認）

- 起動した直後は、どのサーボにも信号を出さない。`sel` で選んだ関節にだけ出す。
- 動く速さを 1 秒に 30°（既定。`speed` で 5〜90）までに抑え、急に動かない。
  **ただし、選んだ最初の1回だけは、サーボが自分の速さで中立へ動きます**（サーボの今の角度をプログラムが知らないため）。
- パルス幅は、どんなコマンドでも 500〜2400 µs の外に出さない。
- 範囲の端（lo / hi）を記録するまでは、学習の範囲より 10° 外までしか動かさない。記録した後は、記録した端の外へは動かさない。
  学習の範囲は、部品が当たる角度の 10° 以上手前に置いてあります（CAD での計算。実物では未確認）。

## 3. 用意するもの

- ESP32-S3 のボードと、パソコンにつなぐ USB ケーブル
- 5V の電源、ブレッドボード、ジャンパー線（[shopping-list.md](shopping-list.md)）
- MG90S サーボ
- （あるとよい）分度器か、角度の線を引いた紙（§7.5 の `mark` に使う）

配線は [assembly-guide.md](assembly-guide.md) §5 のとおりです。信号線（橙）をつなぐ GPIO は関節ごとに決まっています。

| 番号 | 関節 | 場所 | GPIO（**仮**） |
|---:|---|---|---:|
| 0 | `hip_lf` | 左前・股 | 4 |
| 1 | `knee_lf` | 左前・膝 | 5 |
| 2 | `hip_rf` | 右前・股 | 6 |
| 3 | `knee_rf` | 右前・膝 | 7 |
| 4 | `hip_lh` | 左後・股 | 15 |
| 5 | `knee_lh` | 左後・膝 | 16 |
| 6 | `hip_rh` | 右後・股 | 17 |
| 7 | `knee_rh` | 右後・膝 | 18 |

この順番は方策の出力の順番と同じです（`deploy/esp32/firmware/main/servo_map.h`。学習のタスクと MJCF と一致することをテストで固定）。
GPIO の番号は仮の値で、手元のボードで使えるかは型番が分かってから確かめます（未確認）。

## 4. ESP32 と話す（シリアルのコンソール）

ESP32 を USB でパソコンにつなぎ、シリアルの画面を開きます（ESP-IDF を入れたあと、`idf.py -p ポート monitor`。速さは 115200）。
macOS のポート名は `/dev/cu.usbserial-…` か `/dev/cu.usbmodem…` です（`ls /dev/cu.*` で探す）。

起動すると、次のように出ます。

```
サーボの試験・較正モード。方策は動かさない。help でコマンドの一覧
起動直後はどのサーボにもパルスを出さない。sel で1つずつ選ぶ
ok 保存が無いので既定値（servo_map.h、名目値）で始める
```

コマンドを1行打って Enter を押します。打った文字は Enter を押すまで画面に出ないことがあります
（Enter のあとに `> 打った行` が出ます）。返事は `ok …`（できた）、`err …`（できなかった）、`warn …`（注意）で始まります。

| コマンド | すること |
|---|---|
| `help` | コマンドの一覧 |
| `sel J` | 関節 J を選び、信号を出す（初めてなら中立へ）。J は番号 `0`〜`7` か名前 `hip_lf` など |
| `center` | 中立（関節角 0）へ動かす |
| `+` / `-` | 少し動かす。`+` は関節角を増やす（足先が後ろへ）。`+ 3` のように回数も書ける |
| `step U` | `+` / `-` の1回ぶん[µs]（1〜50、既定 5 ≒ 0.5°） |
| `deg A` | 関節角 A[度] へ動かす（例: `deg -20`） |
| `us P` | パルス幅 P[µs] へ動かす（例: `us 1500`） |
| `speed V` | 動く速さ[度/s]（5〜90、既定 30） |
| `test` | 中立 → +10° → -10° → 中立 とゆっくり動かす |
| `zero` | 今の位置を中立（立った姿勢）として記録 |
| `flip` | 向き（sign）を反転 |
| `lo` / `hi` | 今の位置を範囲の端として記録（lo = 足先が前の端、hi = 後ろの端） |
| `clear` | 選んだ関節の lo / hi を消す |
| `mark A` | 今の位置が関節角 A[度] だと記録し、1度あたりのパルス幅と向きを決める（\|A\| は 15 以上） |
| `reset` | 選んだ関節を既定値に戻す |
| `status` | 選んだ関節の状態（目標、今の位置、中立、向き、範囲） |
| `dump` | 全関節の較正を出す（パソコンが読む形。§8） |
| `save` | 保存する（電源を切っても残る） |
| `load` | 保存した値に戻す（保存していない変更は消える） |
| `off` | すべての信号を止める（サーボの力が抜ける） |

`zero`、`lo`、`hi`、`mark` は、サーボが止まってから打ちます（動いている途中だと `err まだ動いている` と出ます）。

## 5. 1個ずつ動くか確かめる（ホーンを付ける前）

届いたサーボを、ホーンを付けずに1個ずつ確かめます。予備の2個も確かめてください。

1. 5V の電源を抜いた状態で、サーボを1個だけ `hip_lf` の場所（GPIO 4）につなぐ（茶 = GND、赤 = +5V、橙 = GPIO 4）。
   ESP32 の GND とブレッドボードの GND をつなぐ。
2. ESP32 を USB でパソコンにつなぎ、シリアルの画面を開く。5V の電源を入れる。
3. `sel hip_lf` と打つ。サーボが中立へ動きます（すでに中立に近ければ、ほとんど動きません）。
4. `test` と打つ。出力軸が少し回って戻ってくれば正常です。
5. `off` と打つ。5V の電源を抜き、次のサーボにつなぎ替えて 3〜5 を繰り返す。

動かない、震える、異音がする場合は §10 を見てください。

## 6. 中立を出してホーンを付ける

ホーン（と脚）は、サーボを中立にした状態で、脚が**立った姿勢**になる向きに付けます（[assembly-guide.md](assembly-guide.md) §4.1）。

1. そのサーボを、付ける関節の GPIO（§3 の表）につなぐ。
2. `sel <関節名>`（例: `sel hip_lf`）と打つ。サーボが中立（1450 µs）へ動いて止まります。
3. `off` と打ち、5V の電源を抜く。**ここから出力軸を回さない。**
4. 組立手順書のとおりにホーンと脚を付ける（股は §4.5、膝は §4.7）。
   スプラインの歯は約 17° 刻みなので、立った姿勢に**いちばん近い歯**で差し込みます。残りのずれ（最大で約 ±9°）は次の §7.2 で直します。

膝は、上腿を胴体に付けたあとで付けます。膝の立った姿勢は「下腿が膝から前下へ伸び、足先が股の軸の真下に来る」向きです。

## 7. 中立・向き・範囲を測る（脚を付けたあと）

関節を1つずつ、**股から先に**、次の 7.1〜7.6 の順で測ります（膝の立った姿勢は、上腿の角度で決まるため）。
ロボットは箱などに載せ、脚が宙に浮いた状態にします。

### 7.1 選ぶ

`sel hip_lf` と打つ。脚が中立へ動きます（§6 で中立にしてあるので、ほとんど動かないはず）。

### 7.2 中立のずれを直す（zero）

1. 横から見て、脚が立った姿勢になっているかを見る（[assembly-guide.md](assembly-guide.md) §4.1 の図。上腿は股から後ろ下へ 30°）。
2. ずれていれば、`+` か `-` を打って少しずつ動かす（1回 5 µs ≒ 0.5°。大きくずれていれば `step 20` で 1回 約 2° に）。
3. 合ったら `zero` と打つ。
4. 120 µs（約 11°）以上動かさないと合わない場合は、ホーンを1歯差し直したほうがよい（検査でも注意が出ます）。

### 7.3 向きを確かめる（flip）

1. `deg 10` と打つ。**足先が後ろ（ロボットのお尻の側）へ動けば正しい**。
2. 足先が前へ動いたら、`flip` と打ち、`deg 10` でもう一度確かめる。
3. `center` で中立に戻す。

膝でも同じです。膝の `deg 10` は脚が少し伸びる向き（足先が後ろへ）です。

### 7.4 範囲の端を決める（lo / hi）

1. 学習の範囲の端（§1 の表）へ動かす。前脚の股なら `deg -45`。脚がゆっくり前へ振れます。
   - 途中で部品どうしが当たりそうなら、すぐ `off` と打つ。当たる少し手前まで `+` / `-` で戻し、そこで記録する。
2. 止まったら `lo` と打つ。
3. 反対の端へ動かす（前脚の股なら `deg 20`）。止まったら `hi` と打つ。
4. `warn … lo（足先が前）と hi（後ろ）が向きと合わない` と出たら、向きが逆です。`flip` してから 7.3 からやり直す
   （`clear` で lo / hi を消す）。

学習の範囲まで動かせなかった関節は、そのまま記録してかまいません。§8 の検査で「学習は -45° まで使う」のように出ます。
その場合は、ホーンの向き・部品の当たり・設計を見直します（設計の担当に伝える）。

### 7.5 （できれば）1度あたりのパルス幅を測る（mark）

既定の 1度 = 10.56 µs は推定値です。分度器か、角度の線を引いた紙があれば測れます。

1. 立った姿勢から 30° 振れた位置に線を引いておく（股なら上腿、膝なら下腿の向き）。
   **前脚の股（`hip_lf`、`hip_rf`）は前へ 30°**（-30°）、ほかは後ろへ 30°（+30°）にする。
   前脚の股を後ろへ 30° 振ると、上腿が胴体に当たる計算です（[hardware-spec.md](hardware-spec.md)「可動域の決め方」）。
2. `+` / `-` で脚を線に合わせる（`deg 30`、前脚の股は `deg -30` で近くまで動かしてから合わせると早い）。
3. `mark 30`（前脚の股は `mark -30`）と打つ。1度あたりのパルス幅と向きが決まります（`err` が出たら、中立と角度を確かめる）。

### 7.6 保存する

`save` と打つ。8 関節を測り終えるまで、1関節ごとに `save` しておくと安心です（途中で電源が切れても残る）。

### 7.7 全部の関節で繰り返す

`hip_lf` → `hip_rf` → `hip_lh` → `hip_rh` → `knee_lf` → `knee_rf` → `knee_lh` → `knee_rh` の順に 7.1〜7.6 を繰り返し、
最後に `dump` で一覧を見ます。電源を入れ直してから `dump` を打ち、同じ値と `saved=1` が出れば、保存できています。

## 8. パソコンで結果を受け取る

シリアルの画面（`idf.py monitor` など）を**閉じてから**、パソコンで次を打ちます（1つのポートは1つのプログラムしか開けない）。
ポートを開くと ESP32 が再起動することがあるので、**先に ESP32 で `save` しておきます**。

```bash
cd robot-project
uv run python -m deploy.esp32.servo_calibration read --port /dev/cu.usbserial-0001 \
    --out deploy/esp32/calibration/mini-r2.json --log deploy/esp32/calibration/mini-r2-dump.log
uv run python -m deploy.esp32.servo_calibration check deploy/esp32/calibration/mini-r2.json
```

`read` がうまくいかないときは、シリアルの画面で `dump` と打ち、`CAL begin` から `CAL end` までをコピーしてファイルに貼り、
`parse` で読みます。

```bash
uv run python -m deploy.esp32.servo_calibration parse 貼ったファイル.txt --out deploy/esp32/calibration/mini-r2.json
```

`check` は関節ごとの表を出し、最後に「合格」か「不合格（エラー n 件）」を出します。エラーの例と直し方:

| 出る言葉 | 直し方 |
|---|---|
| 範囲が未測定 | その関節の `lo` と `hi` を記録して `save` |
| 範囲の端の向きが sign と合わない | `flip` して §7.3 からやり直す |
| 下限 -38.0° まで（学習は -45° まで使う） | 学習の範囲まで動かせていない。当たる場所を見て、設計の担当に伝える |
| 中立が … ホーンを1歯差し直すとよい（注意） | ホーンを1歯ずらして付け直し、§7.2 から |
| save していない値（注意） | ESP32 で `save` してから読み直す |

合格したら、方策の書き出しに渡すファイルと、ファームウェアの既定値のヘッダを作ります。

```bash
uv run python -m deploy.esp32.servo_calibration servo-json deploy/esp32/calibration/mini-r2.json \
    --out deploy/esp32/calibration/servo.json
uv run python -m deploy.esp32.servo_calibration header deploy/esp32/calibration/mini-r2.json \
    --out deploy/esp32/firmware/main/servo_map.h      # NVS が消えても、この値で起動する
```

`servo.json` は、方策を載せる段階で `export_c --servo` に渡します（[esp32-deployment.md](esp32-deployment.md) §8）。
**`firmware/main/policy_weights.h` に本物の方策を置くとサーボが動く設定になる**ので、それは較正が合格し、
吊り下げで試す準備ができてからにします。

## 9. ESP-IDF を入れたあとにすること（開発の作業）

ここまでのプログラムは、ESP-IDF でビルドしていません。入れたあとに次を確かめます。

1. `cd deploy/esp32/firmware && idf.py set-target esp32s3 && idf.py build`。`main.c` と `servo_hal_esp.c` は
   仮のヘッダ（`tests/esp_idf_stubs/`）で構文と型を確かめただけなので、本物のヘッダでエラーが出たら直す。
2. コンソールのポート。ESP-IDF の既定は UART0（ボードの「UART」側の USB 端子。USB シリアル変換の IC を通る）。
   ボードの「USB」側（ESP32-S3 の内蔵 USB）だけでつなぐ場合は、`idf.py menuconfig` で
   コンソールを USB Serial/JTAG にする（二次コンソールは出力だけで、入力を読めない）。手元のボードの型番が分かってから決める。
3. 文字の読み取りが待たずに返るか（`servo_hal_getchar`。`fcntl` で O_NONBLOCK にしている）。止まるなら、UART ドライバを入れて
   `uart_read_bytes` に替える。
4. デューティ 0 で信号が止まり、サーボの力が抜けるか。
5. GPIO 4・5・6・7・15・16・17・18 が手元のボードで使えるか（[assembly-guide.md](assembly-guide.md) §5）。
6. `idf.py -p ポート flash monitor` で書き込み、§5 から始める。
7. 方策の制御ループは `idf.py -DQ8_RUN_POLICY=1 build` で作る（既定は試験・較正モード）。

## 10. うまくいかないとき

| 起きること | 考えられる原因と対処 |
|---|---|
| 何も表示されない | ポートや速さ（115200）が違う。ボードの別の USB 端子を試す（§9 の 2） |
| サーボが動かない | GND を ESP32 とつないでいない。信号線の GPIO が違う。5V の電源が入っていない。3.3V の信号で動かない個体（未確認） |
| 震える、ESP32 が再起動する | 電源が足りない。サーボの赤い線を ESP32 から取っていないか見る。1個ずつにする |
| 「ジー」と鳴り続ける | 部品に当たって押し続けている。すぐ `off`。範囲の端を手前にする |
| `+` で足先が前へ動く | 向きが逆。`flip`（§7.3） |
| `err まだ動いている` | 止まるまで少し待ってから打ち直す |
| 再起動すると値が戻る | `save` していない。`dump` の `saved=0` は保存していないしるし |
| `warn 保存した較正が壊れていた` | 保存がおかしい。測り直して `save` |

## 11. 確かめていないこと

- ESP-IDF でのビルド、ESP32 への書き込み、シリアルのコンソールでの入力（§9）
- 実物の MG90S での動き: パルスを増やしたときに回る向き（名目の向き左 +1・右 -1 は、ホーン側から見て反時計回りと仮定した値）、
  500〜2400 µs で約 180° という値、中立 1450 µs、3.3V の信号で動くか
- 速さの制限が実物で十分に穏やかか（30°/s は決めた値で、試していない）
- 学習の範囲 ±10° まで動かしても部品が当たらないか（CAD での計算だけ）
- NVS への保存と読み出し（ホストではファイルで代わりをした）
- `read`（パソコンでの受け取り）は擬似端末（pty）で確かめた。実物のポートでは未確認
- サーボ1個・8個の消費電流と、充電器で足りるか
