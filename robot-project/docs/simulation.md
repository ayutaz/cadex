# シミュレーション（MuJoCo）

最終確認日: 2026-11-18

## モデルのファイル

| ファイル | 中身 |
|---|---|
| `robot/mjcf/<variant>/model-model.xml` | Cadex が `cadex export` で書いた MJCF そのもの。衝突形状だけを持つ |
| `robot/mjcf/<variant>/visual.xml` | 上に、出力した STL を見た目専用のメッシュとして足したもの（`q8/visual.py`）。追加した形状は `contype=0`・`conaffinity=0` なので、**物理挙動は `model-model.xml` と同じ** |
| `robot/mjcf/<variant>/walk-task.json` | 学習タスク（報酬・終了条件・ランダム化・成功条件・観測）。`training/cadex_train.py` と `cadex evaluate` が読む |

MuJoCo 3.10.0 で読み込み、立位保持・接触・重力・アクチュエータの動作を確認しました。
作る機体は `mini-r2`（mini の脚を組めるように直した形、`leg_rev=2`）です。下の値で機体を書いていないものは、4機体（base・leg120・mini・mini-r2）で同じです。

## モデルの内容

すべて設計スクリプト `robot/design/quadruped8.py` の宣言から Cadex が生成したものです。

### 質量と慣性

各部品の質量・重心・慣性テンソルは、**OCCT の厳密形状の体積 × 密度**で計算されています。

| 部品 | 密度 |
|---|---|
| PLA 印刷部品（胴体・上腿・下腿） | 800 kg/m³（実効密度の推定値） |
| TPU 足先 | 1200 kg/m³ |
| サーボ | カタログ質量 13.4 g に合う実効密度（Cadex が形状から逆算） |
| ESP32-S3・IMU の代用品 | 約9 g・約2 g になる密度（推定） |
| 電池の代用品（base・leg120 のみ。mini・mini-r2 には無い） | 30 g になる密度（仮置き） |
| ボルト | 鋼（7850 kg/m³） |

総質量は mini-r2 で 220.1 g、mini で 228.4 g、base で 275.2 g、leg120 で 280.5 g です（[hardware-spec.md](hardware-spec.md)）。
足先は TPU の密度で計算しています。作るときは PLA で印刷しますが、その質量の差（数 g 以下）はモデルに入れていません。

### 衝突形状

衝突は単純形状だけです（Cadex の MJCF の仕様）。見た目のメッシュは衝突に関わりません。

| 部品 | 形状 | 大きさ（mini-r2・mini / base） | 接触グループ |
|---|---|---|---|
| 胴体（`chassis`） | box | 96 × 62 × 24 mm / 110 × 64 × 24 mm | 既定 |
| 上腿 | capsule | 半径 6.5 mm、長さ 40 mm / 45 mm（上腿長。立位の向きに傾ける） | 1 |
| 下腿 | capsule | 半径 4 mm、長さ 32 mm / 38 mm（下腿長 − 足の直径） | 1 |
| 足先 | sphere | 半径 6 mm、摩擦係数 0.9（推定）。床は MuJoCo の既定の 1.0 で、接触は大きい方をとるので、足と床の摩擦は実際には 1.0 | 2 |

隣り合う部品どうし（シャーシとカバー、シャーシと上腿、上腿と下腿など。base は計34組、電池の無い mini・mini-r2 は33組）の
接触は `<exclude>` で除外されています。
mini-r2 の衝突形状は mini と同じ大きさで、上腿が 3.5 mm、下腿と足先が合わせて 7 mm 外にあります（足先の左右の位置 ±49.8 mm）。
接触の `solref` は 0.004（時定数 4 ms）です。

### アクチュエータ（PWM 角度指令サーボの近似）

MG90S は角度を指令するサーボなので、MuJoCo の位置アクチュエータ（`<general>`、`biastype="affine"`）で表します。
値は 4.8 V のカタログ値（失速トルク 176.5 N·mm、無負荷速度 0.10 s/60°）から決めています。

| 項目 | 値 | 決め方 |
|---|---|---|
| 剛性 | 失速トルク / 5° = 35.3 N·mm/°（MJCF では 2.023 N·m/rad） | 5° ずれると失速トルクに達する |
| アクチュエータの減衰 | 失速トルク / 100 = 1.765 N·mm·s/° | 設計スクリプトの値 |
| トルク上限 | ±176.5 N·mm（失速トルク） | `forcerange` |
| 連続定格（評価用） | 失速の 40% = 70.6 N·mm | 推定。評価指標「RMS トルク / 連続定格」に使う |
| 指令の範囲 | 関節の可動域と同じ | 前脚の股 [-45°, +20°]、後脚の股 [-35°, +45°]、膝 [-60°, +45°] |

### 関節の動特性

| 項目 | 値 | 決め方 |
|---|---|---|
| 関節の粘性 | 失速トルク / 無負荷速度 = 176.5 / 600 = 0.294 N·mm·s/° | 全力時にデータシートの速度（600°/s）で飽和する（Cadex の ADR-409） |
| アーマチュア | 20 kg·mm²（ロータ慣性の出力軸換算） | 推定 |
| 静止摩擦（`frictionloss`） | 2 N·mm | 推定（ギア列） |

### センサー・観測・キーフレーム

| 種類 | MJCF | 方策が読めるか |
|---|---|---|
| IMU の姿勢（四元数） | `framequat`（`c_imu`） | 読める |
| IMU の角速度 | `frameangvel`（`c_imu`） | 読める |
| 前回の関節指令（8） | アクチュエータの指令 | 読める（コントローラ自身が知っている値） |
| 目標速度、歩容の位相（sin/cos） | 学習タスクのゴール | 読める |
| 胴体の速度・位置 | `framelinvel`、`framepos` | 読めない（privileged: 報酬・終了条件・critic 用） |
| 関節角 | `jointpos` | 読めない（PWM サーボは角度を返さないため privileged） |
| 足の接地 | `touch`（足先のサイト） | 読めない（privileged） |
| 足先の位置 | `subtreecom` | 読めない（privileged） |
| サーボの出力トルク | `actuatorfrc` | 読めない（privileged） |

キーフレーム `solved` は関節角 0（立位）です。

### ソルバー

| 項目 | 値 |
|---|---|
| 時間刻み | 2 ms（`solver_step_s=0.002`。MuJoCo の既定値と同じなので MJCF には書かれない） |
| 積分法 | `implicitfast` |
| 制御周期（学習タスク） | 50 Hz（1制御あたり 10 ステップ） |

## 固定モーション（学習なし）

`simulation/fixed_gait.py` は、学習を使わない開ループの動きを MuJoCo で再生し、数値で判定します。
関節の目標角は、足先の軌道から逆運動学（`q8/gait.py`、`q8/robot.py`）で作ります。

```bash
uv run python simulation/fixed_gait.py robot/mjcf/base/visual.xml artifacts/base/fixed_gait --video
```

### 場面

| 場面 | 内容 | 長さ |
|---|---|---|
| 関節の向きの確認 | 胴体を宙に固定し、各関節に +10° を1つずつ指令して、足先が後ろ（-X）へ動くか | 各 0.6 秒 |
| `stand` | 全関節に 0（立位）を指令して保持 | 3 秒 |
| `joint_sweep_hip_lf` | 左前の股だけを ±15°、周期2秒の正弦で動かす（接地したまま） | 4 秒 |
| `trot` | 対角の脚（左前と右後、右前と左後）を交互に振るトロット | 6 秒 |
| `turn` | トロットの歩幅を左右で変えて旋回（`turn=0.4`: 左 0.6 倍、右 1.4 倍） | 6 秒 |

トロットの設定: 周期 0.5 秒、歩幅 40 mm、足上げ 8 mm、立脚率 0.5。歩幅は最初の1秒で 0 から立ち上げます。
指令どおりに足が動いた場合の速度（公称値）は 160 mm/s です。

### 結果（base、`artifacts/base/fixed_gait/fixed_gait.json`）

固定モーションの動画と時系列は base でだけ作りました。mini の固定歩容は、学習済み方策と同じ成功条件（10シード）での
評価だけを行い、合格しませんでした（合格率 0、最少の脚の歩数 0。`artifacts/mini/evaluation-seeds/full-mini-s0/summary.json`、
[experiment-results.md](experiment-results.md) §6）。mini-r2 の固定歩容は評価していません。

| 場面 | 前進速度 | 終了時の向き | 最大傾斜 | 胴体の最大沈み込み | 最大の追従誤差 | 最大トルク（関節） |
|---|---|---|---|---|---|---|
| `stand` | -0.2 mm/s | 0.0° | 0.07° | 0.2 mm | 0.53° | 19.1 N·mm（`knee_lh`） |
| `joint_sweep_hip_lf` | -1.5 mm/s | 2.91° | 0.39° | 0.4 mm | 4.07° | 71.1 N·mm（`hip_lf`） |
| `trot` | **50.2 mm/s**（6秒で 301 mm） | 4.71° | 5.43° | 1.6 mm | 11.87° | 154.8 N·mm（`hip_rh`） |
| `turn` | -16.6 mm/s | **197.83°（約33°/s）** | 5.97° | 1.6 mm | 15.68° | 176.5 N·mm（`hip_rh`、0.9% の時間で上限に到達） |

判定はすべて合格です。

| 判定 | 結果 |
|---|---|
| 全関節が指令した向きに動く（+10° 指令で 10.0° に到達、足先は股で 14.5 mm・膝で 8.1 mm 後ろへ） | 合格 |
| 立位を保持する（傾き 5° 未満、沈み込み 10 mm 未満） | 合格 |
| 関節制限を超えない | 合格 |
| 胴体・脚が床に触れない（足先以外） | 合格 |
| 自己干渉で 0.5 mm 以上めり込まない | 合格（接触なし） |
| トロットで前進する（20 mm/s 超、傾き 30° 未満） | 合格 |

トロットの実速度（50.2 mm/s）は公称値（160 mm/s）の約31% です。追従誤差が最大 11.87° あり、
サーボが指令に追いついていないこと、足が滑っていることが候補ですが、原因は切り分けていません。
同じ固定歩容を学習済み方策と同じ成功条件（10シード）で評価した結果は `artifacts/<variant>/evaluation/` と
[experiment-results.md](experiment-results.md) にあります。

## Sim2Real: 実機との差として想定される点

実機はまだないので、どれも確かめていません。学習と移植で注意が要る点として挙げます。
表の「DR の案」は、実機との差に強くした `mini-r2-p7-eff-dr`（実機の候補 `full-mini-r2-p7-eff-dr-s4` はこの案の乱数 4 の回）です。

- **学習に入れたもの**（DR の案。[training.md](training.md) §5.2）: 足の摩擦、サーボの応答の遅れ（一次遅れ）と剛性とトルク、
  胴体の重心、押し。`q8/dr_bundle.py` のバンドル（Cadex のタスクのランダム化と押し）と、学習器のフラグ
  （`--randomise-friction`・`--randomise-drive-torque`）で入れた。
- **評価にだけ入れたもの**（`q8/robustness.py`。[experiment-results.md](experiment-results.md) §11）: 純粋な遅れ、制御周期のゆらぎ、
  ギアのガタ。評価では、学習に入れたものの多くも幅を変えて入れ、方策がどれだけ弱いかを測った。
- **どちらにも入れていないもの**: IMU のノイズ・バイアス、電源コードの重さと引っ張り、発熱。電源電圧による差は、サーボのトルクの幅（×0.8〜1.1）で一部を近似しただけ。

DR の案は、普通の評価で5回とも合格 10/10、実機を想定した幅を一度に変える評価で合格率 0.84（元の `mini-r2-p7-eff` は 0.60）でした。
どれもシミュレーションの結果で、評価の幅も実測ではなく推定です。

| 項目 | シミュレーションでの扱い | 実機で想定される差 |
|---|---|---|
| PWM サーボの制御 | 理想的な比例 + 減衰の位置制御（5° で失速トルク）。評価では剛性 ×0.6〜1.3、トルク ×0.8〜1.1。学習（DR の案）では剛性 ×0.7〜1.3（関節ごと）、トルク ×0.8〜1.1 | 安価なサーボ内部の制御は不明。**不感帯**（小さな指令変化に反応しない）は未モデル化 |
| ギアのガタ（バックラッシュ） | 学習では未モデル化。評価では、指令と関節角の差が ±幅/2 の内側で押し返さない不感帯（全幅 0〜4°）で近似 | 金属ギアでも数度のガタがありうる。立位や着地で姿勢がふらつく原因になる |
| IMU のノイズ・バイアス | なし（真値）。学習にも評価にも入れていない | MPU-6050 などにはノイズとドリフトがある。**Cadex のトレーナーの観測ノイズは追跡器と荷重センサーにしか無く、IMU には入れられない** |
| 通信・制御の遅延 | 公称ではなし（同じステップで反映）。評価では純粋な遅れ 0〜40 ms と、指令ごとのゆらぎ 0〜20 ms を 2 ms 刻みで入れる。学習（DR の案）ではサーボの一次遅れ 1.5〜30 ms（カットモデルのアクチュエータを一次遅れに書き換えて近似。`q8/dr_bundle.py`） | IMU の読み出し、推論、PWM 更新（サーボは通常 50 Hz）で遅延が出る。**Cadex のトレーナーには純粋な遅れと周期のゆらぎを入れる機能がない** |
| 足の摩擦 | 足 0.9・床 1.0 で、接触は 1.0（固定）。評価では μ 0.3〜1.2、学習（DR の案）では 0.35〜1.25 | 作るときの足先は PLA に滑り止めシートを貼ったもので、摩擦は未確認。床との組み合わせでも大きく変わり、滑りやすい床では歩幅が出ない |
| 電源電圧 | 4.8 V のカタログ値で固定 | mini-r2 は外部の 5V 電源で動かす。電圧でトルクと速度が変わる（MG90S: 4.8 V で 1.8 kg·cm・0.10 s/60°、6.6 V で 2.2 kg·cm、6.0 V で 0.08 s/60°）。8個が同時に動くときの電圧降下は未測定 |
| 電源コード | なし | mini-r2 は外部電源のコードがつながったまま歩く。コードの重さと引っ張りは未モデル化 |
| 連続定格・発熱 | 失速の 40% と推定し、評価指標に使うだけ | 実際の連続定格は不明。長時間の歩行で発熱しトルクが落ちる可能性 |
| 質量・重心 | 印刷の実効密度は推定。学習では胴体の質量を ±15%、電池（base・leg120 のみ）を ±40% でランダム化。DR の案では胴体の重心も x ±2.7 mm・y ±1.8 mm。評価では胴体の質量 ×0.9〜1.2、重心 x ±5 mm・y ±3 mm | 充填率・材料で変わる。mini-r2 は電池を載せない |
| 外からの押し | 公称ではなし。学習（DR の案）では胴体の重心に水平に 0〜1.5 N を 0.1 秒 × 2回。評価では真横から 1.0〜2.5 N を 0.1 秒 | DR の5回で、倒れずに戻った割合は 1.5 N で 0.99、2.0 N で 0.66、2.5 N で 0.03（シミュレーション）。床の段差・傾き、脚に当たる押しは試していない |
| 関節の粘性・摩擦 | 学習では粘性を 0.7〜1.3 倍、摩擦を 0.5〜2.0 倍でランダム化 | 個体差、温度、摩耗 |
| 関節角 0 の位置 | 立位で正確に 0 | サーボの中立とホーンの取付角の誤差（ホーンのスプラインは 21 歯で、約17° 刻みでしか合わせられない）。試験・較正モードで関節ごとに測って補正する（[servo-calibration.md](servo-calibration.md)。実機では未確認） |
| 方策の観測 | 実機で得られるもの（IMU、前回の指令、目標速度、位相）に限定済み | 関節角・接地は観測しない設計なので、この点の差は小さい |
